## 系统概念从 NEVPNManager 的用途开始

Apple 文档将 NEVPNManager 描述为创建、管理 Personal VPN 配置的接口，适用于 iOS 与 macOS。它的典型用途涉及公共 Wi-Fi 等保护不安全网络环境中的浏览活动。这个定义描述开发接口，不提供某款应用完整功能或资源交付说明。

Network Extension 框架的摘要是定制、扩展核心网络功能。这里可以确认框架与配置管理的主题，不据摘要给所有应用补相同的连接范围。框架名字出现在哪个页面，也不等于某个商店应用实际采用全部功能。

[Apple NEVPNManager 官方文档](https://developer.apple.com/documentation/networkextension/nevpnmanager) 用来指代接口资料。它没有在现有正文中给出用户安装应用后添加 VPN 配置的完整授权弹窗，本文就不从 API 名称还原界面。系统能力与授权框文案仍需不同依据。

因此，iOS 系统概念是应用怎样利用配置管理能力的问题，不是本文已经替设备创建了配置。当前没有设备、应用界面或连接记录，不使用已授权、已连接等状态描述。本文不会把一个系统词变成操作完成的证明。

同样，接口的典型场景不是某个服务的当前承诺。本文不从它推出数据经营、节点来源或商业主体，也不提供法律判断。系统文档说到功能定义，具体应用仍需自己的页面。

[Apple App Store 审核指南](https://developer.apple.com/app-store/review/guidelines/) 对应平台原文。本文没有执行审核，也没有读取具体应用全部政策，所以不写通过本文认证、已符合所有条款之类判断。应用自己的声明与平台要求仍是两个对象。

这段政策不被扩成对外部订阅服务的合同，也没有给未知资源经营者建立身份。即使应用有订阅输入，条款的适用对象仍需要保留。本文只讨论已经写明的 iOS 应用规则，不引入其他平台政策。
